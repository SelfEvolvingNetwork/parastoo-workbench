# قرارداد کارگاه — چرخهٔ «اول سندباکس سرور» برای عامل پرستو

این سند قرارداد عملیاتی کارگاه است؛ مکمل `docs/AI_AGENT_LOOP.md` در مخزن پرستو (پروتکل چرخهٔ توسعه) نه جایگزین آن. اگر متناقض شد، پروتکل پرستو بالاتر است و این سند باید اصلاح شود.

## ۱) چرا کارگاه؟ (انگیزهٔ راهبردی)

سندباکس محلی عامل زودگذر است: بین جلسات بازیابی می‌شود، ابزارهایش می‌شکنند و داکر/ایمیج واقعی پرستو را ندارد. سرور مالک برعکس: پایدار است، ایمیج `parastoo/core` با وابستگی‌های پین‌شده دارد و همان جایی است که کد واقعاً مستقر می‌شود. قرار مالک: **آزمایش سنگین همیشه روی سرور**؛ سندباکس محلی فقط برای ویرایش کد و چک‌های سبک.

## ۲) جایگاه کارگاه در چرخهٔ ۹ گامی

| گام | محل اجرا | ابزار |
| --- | --- | --- |
| M0 همگام‌سازی | محلی + پنل | `git pull`، `tests/e2e_live.py` |
| M2 پیاده‌سازی | محلی | ویرایش کد در کلون محلی |
| M3 دروازهٔ پوش (سبک) | محلی | سوئیت‌های آفلاین + ruff + `bash -n` |
| M4 پوش | محلی → گیت‌هاب | `git push origin main` |
| **M3.5 دروازهٔ استقرار (سنگین) — الزامی** | **سرور/کارگاه** | **`wb gate <sha>`** |
| M5 استقرار | پل | `wb deploy` → `wb verify <sha>` |
| M6 راستی‌آزمایی زنده | محلی + پنل | `tests/e2e_live.py --expect-commit` |
| M7/M8 ثبت و گزارش | محلی | WORKLOG + گزارش فارسی به مالک |

**قاعدهٔ سخت:** استقرار (`wb deploy`) بدون دروازهٔ سبز سرور روی همان SHA ممنوع است. دروازهٔ محلی سبک، شرط پوش است؛ دروازهٔ سرور سنگین، شرط استقرار.

## ۳) قرارداد دو دروازه

- **دروازهٔ سبک (محلی، پیش از پوش):** چهار سوئیت آفلاین + ruff (`--select F401,F811,F841`) + `bash -n`. چند ثانیه.
- **دروازهٔ سنگین (سرور، پیش از استقرار):** همان چک‌ها روی درخت کاریِ واقعی کامیتِ پوش‌شده، داخل ایمیج `parastoo/core:latest` با `--network none` — یعنی با همان وابستگی‌هایی که در تولید هست. خروجی در `results/gate-history.log` سرور می‌ماند.
- اگر دروازهٔ سرور قرمز شد: **استقرار لغو**؛ رفع در چرخهٔ جدید (کامیت جبرانی)، هرگز force-push.

## ۴) مرزهای امنیتی

1. کارگاه فقط از پل access-agent فرمان می‌گیرد؛ هیچ مسیر دیگری به سرور نیست.
2. هیچ رازی در کارگاه نوشته نمی‌شود؛ پل خودش احراز می‌کند و audit.jsonl مستقل دارد.
3. `/opt/parastoo`، `.env`، `config/`، `backups/`، `logs/` نصب تولیدی از کارگاه دست نمی‌خورند (§۷ پروتکل پرستو).
4. کار سنگین هم‌زمان با استقرار ممنوع (سرور ۴GB) — `wb gate` و `wb deploy` را هم‌زمان صدا نزن.
5. `results/gate-history.log` سند شفافیت است؛ پاک‌کردن/ویرایشش ممنوع.

## ۵) عیب‌یابی

| نشانه | علت محتمل | کار |
| --- | --- | --- |
| `rexec` کد ۱۲۵ | پل/شبکه/توکن | `wb status`؛ فایل env را چک کن؛ گزارش به مالک |
| دروازه ۱۰ دقیقه تمام نشد | داکر کند/گیر | `wb exec 'tail -30 <log>'`؛ `docker ps`؛ اگر لاشه ماند: cleanup |
| `ruff یافت نیست` در دروازه | ریلیز گیت‌هاب لود نشد | دوباره `wb update` (نصب غیرمرگبار است، دوباره تلاش می‌کند) |
| `کامیت روی سرور در دسترس نیست` | پوش نرسیده | `git ls-remote` محلی؛ بعد دوباره `wb gate` |
| استقرار گیر کرد | پروتکل stall §M5 پرستو | همان پروتکل؛ حدس‌زدن ممنوع |

## ۶) ارتقا و بازنصب

- ارتقای روزمره: تغییر در این مخزن → کامیت/پوش → `wb update`.
- بازسازی کامل سرور: بعد از نصب پرستو، فرمان یک‌خطیِ «نصب روی سرور» در README — کل کارگاه با دروازه و تاریخچه‌اش (در results) برمی‌گردد.

## ۷) آنچه عمداً خارج از دامنه است

- CI گیت‌هاب پرستو، بیلدهای پروژهٔ کاربران، پل `pst_` (پروژه‌محور) — این‌ها به مخزن/قراردادهای خودشان تعلق دارند.
- هر تغییری در خود پرستو از کارگاه **انجام نمی‌شود**؛ کارگاه فقط آزمایشگاه است — تغییر کد همیشه در کلون محلی و با چرخهٔ پرستو است.
